# Pocket Oracle

A pocket tarot grimoire with an **open-weight AI reader**. The complete 78-card Rider-Waite deck — meanings, correspondences, imagery notes — plus a draw ritual and a symbolic reading generated by an open-weight language model.

**Built by Antonio Pasolini and Melissa, an AI agent.**

Built for **Hacktoberfest 2026 · DEV Challenge — Week 2** (theme: *Side Hustle* — build something with open-weight models or open-source AI that someone would actually pay for).

## Origin and credit

This project grows out of **[Tarot Rider-Waite](https://github.com/jrpasolini/Tarot-Rider-Waite)** — an earlier interactive Portuguese-language grimoire of the 78 cards, whose card dataset, card text and draw flow are reused here. The source project carries its own authorship and credits.

**Pocket Oracle is a new build.** It starts on **2026-10-15**, inside the Hacktoberfest 2026 challenge window, and takes that grimoire as its foundation. Everything added in this repository is developed during the challenge window; what came from the source project is credited above and kept clearly separated.

The original Portuguese text of the app is preserved in [`README.pt-BR.md`](README.pt-BR.md).

Rider-Waite card images are public domain, obtained from a collection based on the Wikimedia Commons archive.

## Stack

- **Static PWA** — no build step, no framework, no bundler
- **Cloudflare Worker** (`pocket-tarot-ai`, `cloudflare-worker.js`) at `https://api.jrpasolini.tech` as the AI backend
- **Cloudflare Workers AI** for the readings — an **open-weight** model
- Deployed on **GitHub Pages**

## How it works

1. The user writes a question and draws one card, or three (Past / Present / Future).
2. The front end sends the question, the **names** of the drawn cards and the interface language to the Worker.
3. The Worker resolves each card against a canonical 78-card dataset (Portuguese/English), ignoring editable card descriptions supplied by callers, then builds the prompt and calls an open-weight model through Workers AI.
4. The model returns a **structured JSON reading**, which is validated against the expected shape before being rendered as sections.

The deck itself, the search, the filters and the draws all work **offline** — only the optional AI reading needs the network.

## Data flow and privacy

- **The deck, the search, the filters and the draws work offline.** Only the optional AI reading needs the network.
- **Interpretation:** the browser sends the question and card names to the Cloudflare Worker. The Worker uses trusted card descriptions embedded in its source to call **Gemma 4** via Cloudflare Workers AI (with Llama fallback). The application does not intentionally persist questions, but providers' operational logs and retention policies still apply.
- **Narration (optional):** only when the reader asks to *listen*, the browser sends a short-lived signed authorization issued with that interpretation. The Worker verifies it, then forwards the authorized reading text to **ElevenLabs**. The ElevenLabs API key and signing key live as Worker secrets and never reach the browser. Voice stays disabled until both are configured.
- So two external providers can receive text: **Cloudflare Workers AI** (the reading) and **ElevenLabs** (the narration, only after an explicit click). A reading may echo parts of the reader's question.
- **Rate limiting:** a Cloudflare zone WAF rule was reported in the 2026-10-16 infrastructure handover (30 requests / 10 seconds per IP and data center on `api.jrpasolini.tech`); verify the live rule through Cloudflare before relying on it. The Worker's per-isolate in-memory limits remain secondary, not a distributed/global quota. Check alternate routes and preview URLs before declaring the API protected.
